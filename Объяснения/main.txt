==========================================================================
 main.py — точка входа приложения
==========================================================================

ЗАЧЕМ НУЖЕН ФАЙЛ
----------------
Это файл, который запускают командой  python main.py  (и именно он
становится Planora.exe при сборке PyInstaller-ом). Сам он почти ничего
не делает — только "собирает" приложение из готовых частей:

  1. создаёт объект приложения Qt (QApplication);
  2. подключает оформление из styles/style.qss;
  3. открывает базу данных (класс Database);
  4. создаёт и показывает главное окно (класс MainWindow);
  5. запускает цикл обработки событий;
  6. после закрытия окна закрывает базу и завершает программу.

Вся логика вынесена в другие модули, чтобы точка входа была короткой и
понятной. Это частый вопрос на защите: "почему main.py такой маленький?"
Ответ — разделение ответственности: запуск отдельно, окна отдельно,
база отдельно.


ИМПОРТЫ
-------
  import os, sys
      os — чтобы проверить, существует ли файл стилей (os.path.exists).
      sys — sys.argv (аргументы командной строки, их требует
      QApplication) и sys.exit (завершение программы с кодом возврата).

  from PyQt5.QtCore import Qt
      Qt — пространство имён с константами Qt (флаги, атрибуты).
      Здесь нужна константа Qt.AA_DisableWindowContextHelpButton.

  from PyQt5.QtWidgets import QApplication
      Главный объект любого Qt-приложения.

  from constants import APP_NAME, STYLE_PATH
      Название приложения и путь к файлу стилей — из общих констант.

  from database import Database
  from main_window import MainWindow
      Наши собственные классы: база данных и главное окно.


ФУНКЦИЯ load_stylesheet(path)
-----------------------------
Читает текст файла QSS и возвращает его строкой.

QSS (Qt Style Sheets) — это "CSS для Qt": файл с правилами вида
    QPushButton { border-radius: 8px; background: #18181b; }
которые задают внешний вид виджетов.

Как работает:
  - если файла нет (os.path.exists вернул False) — возвращается пустая
    строка. Это не ошибка: приложение просто запустится со стандартным
    системным видом, а не упадёт;
  - иначе файл открывается через  with open(..., encoding="utf-8")  и
    читается целиком. Кодировка указана явно, потому что в файле стилей
    могут быть русские комментарии, а Windows по умолчанию открывает
    файлы в cp1251.
  - конструкция  with  сама закрывает файл после чтения.


ФУНКЦИЯ main()
--------------
Пошагово:

1) QApplication.setAttribute(Qt.AA_DisableWindowContextHelpButton, True)
   На Windows Qt по умолчанию добавляет в заголовок каждого диалога
   кнопку "?" (старый механизм подсказок "Что это?"). Мы им не
   пользуемся, поэтому кнопку отключаем. ВАЖНО: атрибут задаётся ДО
   создания QApplication, потому что он влияет на создание окон.

2) app = QApplication(sys.argv)
   Создаётся объект приложения. Он обязан существовать раньше любого
   виджета — без него Qt не может создать ни одного окна. Он же
   обрабатывает все события: клики, нажатия клавиш, перерисовку.
   sys.argv передаётся по традиции: Qt умеет читать из командной
   строки свои служебные параметры.

3) app.setApplicationName(APP_NAME)
   Название приложения ("Planora") — Qt использует его в служебных
   местах (например, в заголовках системных диалогов).

4) app.setStyleSheet(load_stylesheet(STYLE_PATH))
   Стиль задаётся всему приложению, а не одному окну. Поэтому правила
   из style.qss действуют сразу во всех окнах и диалогах, в том числе
   в тех, что создаются позже (окно задачи, окно категорий,
   QMessageBox).

5) database = Database()
   Открывается база данных. При первом запуске класс Database сам
   создаст файл planora.db, три таблицы и пять категорий по умолчанию
   (подробно — в объяснении database.py).

6) window = MainWindow(database)
   window.show()
   Создаётся главное окно, ему передаётся уже готовая база. Окно не
   создаёт базу само — так оно не зависит от того, где лежит файл БД
   (это называется "передача зависимости снаружи").
   show() делает окно видимым — без этого вызова окно существовало бы
   в памяти, но на экране его бы не было.

7) exit_code = app.exec_()
   Запускается ЦИКЛ ОБРАБОТКИ СОБЫТИЙ (event loop). Это ключевое
   понятие Qt: программа не выполняется "сверху вниз до конца", а
   крутится в бесконечном цикле, ждёт событий (клик, нажатие клавиши)
   и вызывает для них нужные обработчики. Функция exec_() не
   возвращает управление, пока пользователь не закроет последнее окно.
   Подчёркивание в конце имени — наследие Python 2, где exec было
   зарезервированным словом.

8) database.close()
   Выполняется только после закрытия окна (когда exec_() вернул
   управление). Соединение с базой закрывается аккуратно.

9) sys.exit(exit_code)
   Программа завершается с кодом, который вернул Qt (0 — всё хорошо).


БЛОК if __name__ == "__main__":
-------------------------------
Переменная __name__ равна "__main__" только тогда, когда файл запущен
напрямую (python main.py). Если же какой-то другой модуль сделает
import main, то __name__ будет равно "main", и приложение не запустится
само по себе. Это стандартная защита в Python.


ВОЗМОЖНЫЕ ВОПРОСЫ НА ЗАЩИТЕ
---------------------------
В: Что будет, если убрать app.exec_()?
О: Окно мелькнёт и программа сразу завершится — нет цикла событий,
   который держал бы её живой и обрабатывал действия пользователя.

В: Почему база закрывается после exec_(), а не раньше?
О: Потому что exec_() работает всё время жизни программы. Код после
   него выполняется только когда пользователь закрыл окно.

В: Что будет, если удалить style.qss?
О: Ничего страшного: load_stylesheet вернёт пустую строку, приложение
   запустится со стандартным видом Windows.
