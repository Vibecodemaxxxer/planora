==========================================================================
 task_dialog.py — окно создания и редактирования задачи
==========================================================================

ЗАЧЕМ НУЖЕН ФАЙЛ
----------------
Форма окна — ui/task_dialog.ui (Qt Designer), здесь её поведение:
заполнение полей, подзадачи, прикрепление картинки, проверка,
сохранение в базу и удаление.

ОДНО ОКНО — ДВА РЕЖИМА. Режим определяется параметром task_id:
  task_id is None — создание новой задачи, кнопка "Удалить" скрыта;
  task_id задан   — редактирование: поля заполняются из базы, кнопка
                    "Удалить" видна.
Почему не два разных окна: поля и проверки одинаковые, различий всего
несколько строк. Два класса дублировали бы код.

ПОДЗАДАЧИ ЖИВУТ В ПАМЯТИ, пока окно открыто (список self._subtasks), и
пишутся в базу только при "Сохранить". Если бы каждый добавленный
пункт сразу записывался в базу, то "Отмена" отменила бы изменения
полей, но оставила бы новые пункты — неожиданно для пользователя.


ИМПОРТЫ
-------
  uic — загрузка .ui.
  QDate — даты; QEvent — типы событий (для двойного клика);
  QSize — размер иконок; Qt — константы.
  QIcon, QKeySequence, QPixmap — иконка, сочетание клавиш, картинка.
  QDialog, QFileDialog, QLabel, QListWidgetItem, QShortcut, QVBoxLayout.
  Константы, Database, ask_yes_no и show_warning из dialogs.py.


КЛАСС TaskDialog(QDialog)
-------------------------
Наследник QDialog — корневой виджет task_dialog.ui тоже QDialog.

КОНСТРУКТОР __init__(self, database, task_id=None, parent=None)
  self._db = database
  self._task_id = task_id        — None = режим создания
  self._image_path = None        — путь к картинке
  self._subtasks = []            — [{"text": ..., "is_done": ...}, ...]
      Порядок элементов списка = порядок пунктов на экране = столбец
      position в базе.

  uic.loadUi(TASK_DIALOG_UI, self) — виджеты формы становятся
      атрибутами: self.titleLineEdit, self.saveButton и т.д.

  _prepare_widgets(), _connect_signals()

  Ветвление по режиму:
    создание: заголовок "Новая задача", deleteButton.hide() (удалять
      нечего), срок по умолчанию — сегодня, приоритет — "Средний";
    правка: заголовок "Редактирование задачи", _load_task().

  _show_image_preview(), _refresh_subtasks_list() — показать картинку
  и подзадачи.


_prepare_widgets()
------------------
  priorityComboBox.addItems(PRIORITIES) — приоритеты из констант
      (одно место правки).
  categoryComboBox: первый пункт "Без категории" со скрытыми данными
      None, дальше категории из базы, у каждой в скрытых данных id.
      Заполняется кодом, потому что пользователь меняет категории во
      время работы — в Designer их не пропишешь.
  _prepare_deadline_edit() — настройка поля срока (см. ниже).

  imagePreviewLabel.setScaledContents(False)
      Если включено, QLabel растягивает картинку на весь свой размер,
      искажая пропорции. Выключаем — масштабируем сами.
  setAlignment(Qt.AlignCenter) — картинка/текст по центру.

  Иконки на кнопках "Прикрепить" и "Удалить", иконка окна.

  self.imagePreviewLabel.installEventFilter(self) — ФИЛЬТР СОБЫТИЙ
      Нужно поймать двойной клик по превью. Превью — обычный QLabel из
      формы, у него нет своего класса, и переопределить у него
      mouseDoubleClickEvent (как в карточке) негде.
      installEventFilter(self) говорит Qt: "все события этой метки
      сначала пропускай через метод eventFilter объекта self". Там и
      ловим двойной клик.


_prepare_deadline_edit() — КАК СДЕЛАТЬ "ПУСТУЮ" ДАТУ
----------------------------------------------------
QDateEdit не умеет быть пустым — в нём всегда какая-то дата. А у
задачи срока может не быть. Приём:
  setMinimumDate(2000-01-01) — минимальная дата — заведомо
      "нерабочая", раньше неё выбрать нельзя;
  setSpecialValueText("Без срока") — когда в поле стоит минимальная
      дата, вместо неё показывается этот текст.
Пользователь видит "Без срока", а код понимает: дата == минимальной —
значит срока нет.
  setDisplayFormat("dd.MM.yyyy") — формат показа.


_connect_signals()
------------------
  addSubtaskButton.clicked      -> _add_subtask
  newSubtaskLineEdit.returnPressed -> _add_subtask
      returnPressed — нажатие Enter в поле. Пункты удобно добавлять с
      клавиатуры, не тянясь к мыши (КЛАВИАТУРА).
  subtasksListWidget.itemChanged -> _on_subtask_changed
      Срабатывает при любом изменении пункта, в том числе при клике по
      его галочке.
  attachImageButton.clicked -> _choose_image
  saveButton.clicked        -> _save_task
  deleteButton.clicked      -> _delete_task
  cancelButton.clicked      -> self.reject
      reject() — штатный метод QDialog: закрыть окно с результатом
      "отказ". Клавишу Esc QDialog обрабатывает сам тем же reject() —
      отдельно программировать не нужно (требование ТЗ "Esc — закрыть
      окно задачи" выполнено встроенным поведением).

  QShortcut Delete на списке подзадач с контекстом WidgetShortcut:
      удаляет выделенный пункт, но только когда фокус в списке. В поле
      ввода Delete по-прежнему удаляет символы.


_load_task() — ЗАГРУЗКА ЗАДАЧИ В ПОЛЯ (режим правки)
----------------------------------------------------
  task = self._db.get_task(self._task_id)
  Если задачи нет (None) — reject() и выход. Сюда попасть не должны, но
  работать с "пустотой" нельзя.

  titleLineEdit.setText(...), descriptionTextEdit.setPlainText(...)
      task["description"] or "" — если описание None, подставляем
      пустую строку (setPlainText(None) вызвал бы ошибку).

  Срок: если есть — QDate.fromString(строка, формат_базы); если нет —
      минимальная дата (= "Без срока").

  priorityComboBox.setCurrentText(...) — выбрать пункт по тексту.

  categoryComboBox.findData(task["category_id"])
      Ищет пункт по СКРЫТЫМ данным (id). Если не найден — вернёт -1,
      поэтому max(index, 0) подставит "Без категории".

  self._image_path = task["image_path"]

  self._subtasks = [{"text": ..., "is_done": bool(...)} for row in ...]
      Списковое включение (list comprehension): подзадачи из базы
      переносятся в список в памяти. Дальше окно работает только с ним.


ПОДЗАДАЧИ
---------
_refresh_subtasks_list()
    Перестраивает QListWidget по данным self._subtasks.
    blockSignals(True/False) — пока мы сами наполняем список,
      itemChanged срабатывал бы на каждый пункт и портил бы данные,
      по которым список строится.
    Для каждого пункта:
      item.setFlags(item.flags() | Qt.ItemIsUserCheckable)
        ФЛАГИ — набор возможностей пункта. Оператор | (побитовое "или")
        ДОБАВЛЯЕТ флаг "пользователь может ставить галочку" к уже
        имеющимся. Qt сам нарисует чекбокс у пункта.
      item.setCheckState(Qt.Checked / Qt.Unchecked) — состояние.

_add_subtask()
    Текст из поля без пробелов по краям (strip). Пустой — не
    добавляем. Иначе — append в список, очистить поле, перерисовать.

_delete_subtask()
    currentRow() — номер выделенной строки, -1 если ничего не
    выделено. del self._subtasks[row] и перерисовка.

_on_subtask_changed(item)
    row(item) — номер пункта; он совпадает с индексом в _subtasks,
    потому что список строится в том же порядке. Записываем новое
    состояние галочки в память.


КАРТИНКА (МУЛЬТИМЕДИА)
----------------------
_choose_image() — СТАНДАРТНЫЙ ДИАЛОГ QFileDialog
    path, _ = QFileDialog.getOpenFileName(self, заголовок, "", фильтр)
      Открывает стандартное окно выбора файла Windows. Возвращает пару
      (путь, выбранный фильтр). Фильтр нам не нужен — "_" по
      соглашению означает "это значение игнорируем".
      "" — начальная папка (по умолчанию).
      Фильтр — "Изображения (*.png *.jpg ...);;Все файлы (*)".
    Если path пустой — пользователь нажал "Отмена".
    Иначе запоминаем путь и показываем превью.

_show_image_preview()
    В базе хранится ПУТЬ к файлу, а не сама картинка. Файл могли
    удалить или переименовать — это нужно обработать.
    - нет пути: clear(), текст "нет фото", пустая подсказка;
    - pixmap = QPixmap(путь) — QPixmap: картинка, готовая к показу;
    - pixmap.isNull() — файл не картинка / не читается: предупреждение
      show_warning, путь сбрасывается, метод вызывает сам себя
      (теперь уже без пути — покажет "нет фото");
    - иначе pixmap.scaled(размер_метки, Qt.KeepAspectRatio,
      Qt.SmoothTransformation): уменьшить под метку, сохранив
      пропорции, со сглаживанием. В подсказку кладётся путь.

eventFilter(watched_object, event) — ПЕРЕХВАТ ДВОЙНОГО КЛИКА (МЫШЬ)
    Qt вызывает этот метод для каждого события метки превью (мы
    подписались через installEventFilter).
      watched_object — чей это событие (наша метка?);
      event.type() == QEvent.MouseButtonDblClick — это двойной клик?
    Если да и картинка есть — открываем крупно и return True:
      "событие обработано, дальше не передавать".
    Во всех остальных случаях — super().eventFilter(...), то есть
    событие идёт своим обычным путём (иначе метка перестала бы,
    например, перерисовываться).

_show_image_full_size()
    Открывает картинку в отдельном окне.
    - Слишком большие (> 800 px по большей стороне) уменьшаются, чтобы
      окно не вылезло за экран.
    - viewer = QDialog(self) — простое окно, созданное кодом (форма
      из Designer тут не нужна — в нём один элемент).
    - QLabel с картинкой, QVBoxLayout с нулевыми отступами: раскладка
      заставляет окно подобрать размер под картинку.
    - viewer.exec_() — показать модально.


СОХРАНЕНИЕ И УДАЛЕНИЕ
---------------------
_save_task()
    1) ПРОВЕРКА: название обязательно. Если пустое — show_warning,
       курсор в поле названия, return. Окно НЕ закрывается —
       пользователь может исправить.
    2) Собираем словарь fields: title, description, deadline
       (_collect_deadline), priority, category_id (currentData —
       скрытый id), image_path.
    3) Создание: self._task_id = self._db.add_task(**fields)
         ** РАСПАКОВЫВАЕТ словарь в именованные аргументы:
         add_task(title=..., description=..., ...). add_task вернёт id
         новой задачи — он нужен для записи подзадач.
       Правка: self._db.update_task(self._task_id, **fields)
    4) _save_subtasks() — записать подзадачи.
    5) self.accept() — закрыть окно с результатом "принято". По нему
       главное окно понимает, что нужно обновить списки.

_collect_deadline()
    Дата в поле == минимальной -> None ("Без срока").
    Иначе дата строкой в формате базы "yyyy-MM-dd".

_save_subtasks()
    clear_subtasks(task_id) — удалить старые пункты, затем add_subtask
    для каждого из памяти. Порядок и галочки всегда совпадают с тем,
    что пользователь видел в окне.

_delete_task()
    ask_yes_no "Удалить задачу «...»?". При "Да" — delete_task (подзадачи
    удалятся каскадом в базе) и accept().


КАК ЗАКРЫВАЮТСЯ КРИТЕРИИ В ЭТОМ ФАЙЛЕ
-------------------------------------
  Форма из Designer: task_dialog.ui.
  Виджеты: QLineEdit, QTextEdit, QDateEdit, QComboBox, QListWidget,
           QLabel, QPushButton.
  Стандартные диалоги: QFileDialog, QMessageBox.
  Мультимедиа: картинка-вложение с превью и просмотром крупно.
  БД: чтение (get_task, get_subtasks), запись (add_task, add_subtask),
      изменение (update_task), удаление (delete_task, clear_subtasks).
  Клавиатура: Enter в поле подзадачи, Delete в списке, Esc.
  Мышь: двойной клик по превью (eventFilter), галочки подзадач.


ВОЗМОЖНЫЕ ВОПРОСЫ НА ЗАЩИТЕ
---------------------------
В: Как одно окно работает и для создания, и для правки?
О: По параметру task_id: None — создание, число — правка. Отличаются
   только заголовок, кнопка "Удалить" и загрузка данных.

В: Как сделан срок "Без срока", если QDateEdit не бывает пустым?
О: Минимальная дата + specialValueText. Если выбрана минимальная дата,
   в базу пишется NULL.

В: Что такое eventFilter и зачем он здесь?
О: Способ перехватить события чужого виджета. Превью — обычный QLabel
   без своего класса, поэтому двойной клик ловится фильтром событий.

В: Почему подзадачи не пишутся в базу сразу?
О: Чтобы "Отмена" отменяла всё, включая добавленные пункты.

В: Что если файл картинки удалили?
О: QPixmap.isNull() вернёт True — показывается предупреждение,
   программа не падает.

В: Чем accept() отличается от reject()?
О: Оба закрывают диалог, но exec_() вернёт Accepted или Rejected
   соответственно — по этому главное окно решает, обновлять ли списки.
