==========================================================================
 constants.py — все константы проекта
==========================================================================

ЗАЧЕМ НУЖЕН ФАЙЛ
----------------
Здесь собраны все "магические" значения: пути к файлам, тексты надписей,
цвета, размеры, горячие клавиши. В остальном коде нет строк вроде
"#ef4444" или "Ctrl+N" — только имена констант (PRIORITY_COLORS,
SHORTCUT_NEW_TASK).

Зачем так делать:
  - одно место правки: чтобы поменять цвет "просрочено" или текст
    предупреждения, не нужно искать его по всем файлам;
  - код читается лучше: CALENDAR_DOT_SIZE понятнее, чем число 5;
  - это прямо требуется критерием оценивания "обозначение необходимых
    констант".

Константы по соглашению PEP8 пишутся ЗАГЛАВНЫМИ_БУКВАМИ. Python не
запрещает их менять, но заглавные буквы говорят программисту: "это не
меняется во время работы".


РАЗДЕЛ 1. ПУТИ К ФАЙЛАМ (самое важное в этом файле)
---------------------------------------------------
  BASE_DIR = os.path.dirname(os.path.abspath(__file__))

  __file__ — путь к самому файлу constants.py.
  os.path.abspath — делает путь полным (C:\...\planora\constants.py).
  os.path.dirname — отрезает имя файла, остаётся папка проекта.

Почему не просто "ui/main_window.ui"? Относительный путь считается от
ТЕКУЩЕЙ РАБОЧЕЙ ПАПКИ — той, откуда запустили программу. Если запустить
python planora\main.py из рабочего стола, программа искала бы
"рабочий стол\ui\..." и не нашла бы форму. Путь от __file__ всегда
указывает в папку проекта, откуда бы ни запускали.

Два каталога: RESOURCES_DIR и DATA_DIR
  if getattr(sys, "frozen", False):
      RESOURCES_DIR = sys._MEIPASS
      DATA_DIR = os.path.dirname(sys.executable)
  else:
      RESOURCES_DIR = BASE_DIR
      DATA_DIR = BASE_DIR

  - sys.frozen — атрибут, который PyInstaller добавляет в модуль sys
    внутри собранного .exe. При обычном запуске его нет, поэтому
    getattr(..., False) вернёт False (getattr с третьим аргументом не
    падает, если атрибута нет).
  - Когда программа собрана в один .exe, при запуске она распаковывает
    свои файлы (формы, стили, иконки) во ВРЕМЕННУЮ папку. Путь к ней
    лежит в sys._MEIPASS. Отсюда берём ресурсы.
  - Но базу данных туда класть нельзя: временная папка удаляется при
    закрытии программы, и все задачи пропадали бы. Поэтому база лежит
    рядом с самим .exe: sys.executable — путь к запущенному Planora.exe.
  - При обычном запуске из исходников оба каталога — папка проекта.

Дальше из этих каталогов собираются конкретные пути через
os.path.join (он сам ставит правильный разделитель \ или /):
  DB_PATH                — файл базы planora.db
  UI_DIR, MAIN_WINDOW_UI, TASK_DIALOG_UI, CATEGORIES_DIALOG_UI
                         — формы Qt Designer
  ICONS_DIR, ICON_*      — иконки интерфейса (png)
  STYLE_PATH             — файл оформления style.qss
  ICON_SIZE = 18         — до какого размера уменьшать иконки на кнопках

РАЗДЕЛ 3. ПРИОРИТЕТЫ
--------------------
  PRIORITY_HIGH / PRIORITY_MEDIUM / PRIORITY_LOW — тексты приоритетов.
  PRIORITIES — список в порядке важности. Из него заполняется выпадающий

РАЗДЕЛ 5. СОСТОЯНИЯ ДЕДЛАЙНА
----------------------------
  DEADLINE_OVERDUE "Просрочено", DEADLINE_TODAY "Сегодня",
  DEADLINE_TOMORROW "Завтра", DEADLINE_DONE "Выполнено",
  DEADLINE_NO_DATE "Без срока" — тексты цветной метки на карточке.

  DEADLINE_SOON_TEMPLATE = "Через {} дн." — шаблон; вместо {} методом
  .format() подставляется число дней.

  DEADLINE_SOON_KEY = "soon" — служебный ключ. Текст "Через 3 дн." каждый
  раз разный, поэтому использовать его ключом в словаре цветов нельзя —
  вместо него используется фиксированное слово "soon".

  DEADLINE_STATE_COLORS — словарь {состояние: цвет}.


РАЗДЕЛ 6. ФОРМАТЫ ДАТ
---------------------
  DATE_FORMAT_DB = "yyyy-MM-dd"       — как дата хранится в базе
  DATE_FORMAT_DISPLAY = "dd.MM.yyyy"  — как дата показывается человеку

Почему в базе ISO-формат (2026-09-27): такие строки сортируются по
алфавиту в том же порядке, что и по времени. "2026-01-05" < "2026-12-01"
и как строки, и как даты. С форматом 05.01.2026 это не работает
("05.01..." и "01.12..." сравнивались бы по дню, а не по году).

Шаблоны записаны в синтаксисе Qt (yyyy, MM, dd), потому что передаются
в QDate.toString() / QDate.fromString().

РАЗДЕЛ 10. ЦВЕТА И РАЗМЕРЫ КАЛЕНДАРЯ
------------------------------------
  CALENDAR_*_COLOR / CALENDAR_*_BG — цвета текста дней, шапки,
  выбранного дня, фона, сегодняшнего дня, дней соседнего месяца.
  CALENDAR_CELL_RADIUS, CALENDAR_CELL_MARGIN — скругление и отступ
  подложки под днём.
  CALENDAR_DOT_SIZE, CALENDAR_DOT_COLOR, CALENDAR_DOT_OVERDUE_COLOR —
  точка под днём с дедлайном (чёрная / красная, если есть просрочка).

  по палитре и форматам текста, и файл стилей до них не достаёт.
  Поэтому их использует task_calendar.py при ручной отрисовке.

ВОЗМОЖНЫЕ ВОПРОСЫ НА ЗАЩИТЕ
---------------------------
В: Зачем два каталога RESOURCES_DIR и DATA_DIR?
О: В .exe ресурсы распаковываются во временную папку, которая
   удаляется при выходе. Если бы база лежала там же, задачи терялись бы
   после каждого закрытия программы. Поэтому база — рядом с .exe.

В: Почему дата в базе хранится строкой, а не числом?
О: В SQLite нет отдельного типа "дата". ISO-строка yyyy-MM-dd читается
   человеком и при этом правильно сортируется.
