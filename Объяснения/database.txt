==========================================================================
 database.py — работа с базой данных SQLite
==========================================================================

ЗАЧЕМ НУЖЕН ФАЙЛ
----------------
Здесь класс Database — единственное место в проекте, где пишется SQL.
Окна и диалоги никогда не обращаются к базе напрямую: они вызывают
методы вроде db.add_task(...) или db.get_categories().

Это называется инкапсуляция: детали хранения спрятаны внутри класса.
Плюсы:
  - если поменять устройство базы, переписывать нужно только этот
    файл, а не все окна;
  - SQL не перемешан с кодом интерфейса, оба читаются проще.

Этот файл закрывает критерий "работа с БД (чтение, запись, изменение),
не менее двух таблиц" — у нас три связанные таблицы и все операции
CRUD: Create (создание), Read (чтение), Update (изменение), Delete
(удаление).


ИМПОРТЫ
-------
  import sqlite3 — встроенный в Python модуль для SQLite. Ставить ничего
      не нужно, а сама база — это один файл planora.db.
  from datetime import date — чтобы записать дату создания задачи.
  from typing import Any, List, Optional, Tuple — аннотации типов
      (подсказки, что функция принимает и возвращает). На работу
      программы не влияют, только делают код понятнее:
        Optional[str] — "строка или None";
        List[...] — список; Tuple[int, int] — пара чисел; Any — что угодно.
  from constants import DB_PATH, DEFAULT_CATEGORIES


СХЕМА БАЗЫ (три таблицы)
------------------------
  categories: id, name, color
  tasks:      id, title, description, deadline, priority, category_id,
              is_done, image_path, created_at
  subtasks:   id, task_id, text, is_done, position

Связи:
  tasks.category_id  -> categories.id   (у задачи одна категория)
  subtasks.task_id   -> tasks.id        (у задачи много подзадач)
Это связи "один ко многим".


МЕТОД __init__(self, db_path=DB_PATH)
-------------------------------------
Конструктор, выполняется при  Database().

1) self._connection = sqlite3.connect(db_path, check_same_thread=False)
   Открывает файл базы. ЕСЛИ ФАЙЛА НЕТ — SQLite СОЗДАЁТ ЕГО САМ. Поэтому
   planora.db не хранится в репозитории: он появляется при первом
   запуске.
   check_same_thread=False разрешает обращаться к соединению не только
   из того потока, где оно создано. У нас поток один, это просто запас.
   Подчёркивание в начале имени (_connection) по соглашению Python
   означает "внутреннее, снаружи класса не трогать".

2) self._connection.row_factory = sqlite3.Row
   По умолчанию sqlite3 возвращает строки как кортежи: row[1].
   С sqlite3.Row к полю можно обращаться по имени: row["title"].
   Это делает весь остальной код гораздо читаемее.

3) self._connection.execute("PRAGMA foreign_keys = ON")
   ВАЖНАЯ ОСОБЕННОСТЬ SQLite: по умолчанию он НЕ проверяет внешние
   ключи (FOREIGN KEY) и НЕ выполняет ON DELETE CASCADE. Их нужно
   включать командой PRAGMA для каждого нового соединения. Без этой
   строки подзадачи удалённой задачи оставались бы в базе "сиротами".

4) self._create_tables() — создать таблицы, если их ещё нет.
5) self._seed_default_categories() — при первом запуске создать
   категории по умолчанию.


МЕТОД _create_tables()
----------------------
Выполняет три запроса CREATE TABLE IF NOT EXISTS. Благодаря
"IF NOT EXISTS" метод можно вызывать при каждом запуске: если таблица
уже есть, запрос ничего не делает.

Разбор ключевых слов SQL:
  INTEGER PRIMARY KEY AUTOINCREMENT — уникальный номер строки, база
      выдаёт его сама (1, 2, 3...), номера удалённых строк не
      переиспользуются.
  TEXT NOT NULL — текст, пустым (NULL) быть не может.
  UNIQUE — в столбце не может быть двух одинаковых значений. У нас так
      объявлено categories.name: две категории "Работа" создать нельзя —
      база выбросит ошибку sqlite3.IntegrityError, её ловит окно
      категорий.
  DEFAULT 0 — значение, если при вставке его не указали.
  is_done INTEGER — в SQLite нет типа boolean, поэтому "выполнено"
      хранится числом: 0 — нет, 1 — да.

Внешние ключи:
  FOREIGN KEY (category_id) REFERENCES categories (id)
      ON DELETE SET NULL
    Если категорию удалить, у её задач category_id станет NULL (без
    категории). На практике до этого не доходит: окно категорий
    запрещает удалять категорию с задачами. Это "страховка" на уровне
    базы.

  FOREIGN KEY (task_id) REFERENCES tasks (id)
      ON DELETE CASCADE
    Каскадное удаление: при удалении задачи база САМА удалит все её
    подзадачи. Требование ТЗ.

self._connection.commit() — фиксирует изменения. Пока не вызван commit,
изменения видны только в текущем соединении и не записаны на диск
окончательно.


МЕТОД _seed_default_categories()
--------------------------------
"Seed" — "посеять" начальные данные. Если get_categories() вернул
пустой список (первый запуск), для каждой пары (name, color) из
DEFAULT_CATEGORIES вызывается add_category. Если категории уже есть —
return, ничего не делаем. Пустой список в Python считается "ложью",
поэтому if self.get_categories() проверяет "есть ли хоть одна".


КАТЕГОРИИ
---------
get_categories()
    SELECT id, name, color FROM categories ORDER BY name
    Все категории по алфавиту. fetchall() возвращает список строк.

add_category(name, color)
    INSERT INTO categories (name, color) VALUES (?, ?)
    Возвращает cursor.lastrowid — id только что вставленной строки.

rename_category(category_id, new_name)
    UPDATE categories SET name = ? WHERE id = ?

set_category_color(category_id, color)
    UPDATE categories SET color = ? WHERE id = ?

category_has_tasks(category_id)
    SELECT COUNT(*) FROM tasks WHERE category_id = ?
    fetchone()[0] — первое (единственное) значение единственной строки.
    Возвращает True, если задач больше нуля. Используется перед
    удалением категории (по ТЗ категорию с задачами удалять нельзя).

delete_category(category_id)
    DELETE FROM categories WHERE id = ?


ПАРАМЕТРЫ "?" — ЗАЩИТА ОТ SQL-ИНЪЕКЦИЙ (частый вопрос!)
--------------------------------------------------------
Значения никогда не вклеиваются в текст запроса через f-строку или +.
Вместо них в SQL стоят знаки вопроса, а значения передаются вторым
аргументом кортежем:
    execute("DELETE FROM tasks WHERE id = ?", (task_id,))
sqlite3 сам безопасно подставит значение. Если бы пользователь ввёл
название вида  '); DROP TABLE tasks; --  , оно было бы записано как
обычный текст, а не выполнено как команда.
Запятая в (task_id,) обязательна: без неё это не кортеж, а просто
число в скобках.


ЗАДАЧИ
------
add_task(title, description, deadline, priority, category_id,
         image_path=None)
    INSERT INTO tasks (...) VALUES (?, ?, ?, ?, ?, 0, ?, ?)
    is_done сразу 0 (новая задача не выполнена).
    created_at — date.today().isoformat(), то есть "2026-09-27". Дата
    создания проставляется автоматически, пользователь её не вводит.
    Возвращает id новой задачи — он нужен окну задачи, чтобы потом
    записать подзадачи.

update_task(task_id, **fields)
    Обновляет ТОЛЬКО переданные поля. Пример вызова:
        db.update_task(5, title="Новое", priority="Высокий")
    **fields собирает именованные аргументы в словарь:
        {"title": "Новое", "priority": "Высокий"}
    Дальше:
      columns = "title = ?, priority = ?"
      values  = ["Новое", "Высокий", 5]
      SQL: UPDATE tasks SET title = ?, priority = ? WHERE id = ?
    Если полей не передали — return, ничего не делаем.

    Почему имена столбцов подставляются f-строкой — это не дыра?
    Через "?" можно передавать только ЗНАЧЕНИЯ, а имена столбцов —
    нельзя. Имена полей приходят только из нашего кода (ключи словаря,
    которые пишем мы), а не из ввода пользователя, поэтому это
    безопасно. Сами значения по-прежнему идут через "?".

set_task_done(task_id, is_done)
    Короткая обёртка: update_task(task_id, is_done=int(is_done)).
    int(True) = 1, int(False) = 0.

delete_task(task_id)
    DELETE FROM tasks WHERE id = ?
    Подзадачи удалятся сами (ON DELETE CASCADE).

get_tasks()
    SELECT * FROM tasks ORDER BY deadline IS NULL, deadline
    Хитрость сортировки: выражение "deadline IS NULL" даёт 0 для задач
    со сроком и 1 для задач без срока. Сортировка сначала по нему
    ставит задачи без срока в конец, а потом внутри — по дате.

get_task(task_id)
    Одна задача по id. fetchone() возвращает строку или None, если
    такой задачи нет.

get_tasks_by_date(iso_date)
    SELECT * FROM tasks WHERE deadline = ? ORDER BY priority
    Задачи с дедлайном ровно в указанный день — для режима "Календарь".


ПОДЗАДАЧИ
---------
add_subtask(task_id, text, is_done=False)
    Сначала узнаёт следующий номер position (_next_subtask_position),
    затем INSERT. position нужен, чтобы пункты всегда выводились в том
    порядке, в каком их добавили.

clear_subtasks(task_id)
    DELETE FROM subtasks WHERE task_id = ?
    Удаляет все подзадачи задачи. Используется при сохранении окна
    задачи: проще стереть старый список и записать новый целиком, чем
    вычислять, что добавили, что удалили, где сменилась галочка.
    Подзадач у задачи единицы — это дёшево.

_next_subtask_position(task_id)
    SELECT COALESCE(MAX(position), -1) + 1 FROM subtasks WHERE task_id=?
    MAX(position) — наибольший номер у этой задачи. Если подзадач нет,
    MAX вернёт NULL; COALESCE(x, -1) заменяет NULL на -1. Итог +1:
    для первой подзадачи 0, для следующей 1 и т.д.

get_subtasks(task_id)
    Все подзадачи задачи, отсортированные по position.

count_subtasks(task_id)
    SELECT COALESCE(SUM(is_done), 0), COUNT(*) FROM subtasks WHERE ...
    Возвращает пару (выполнено, всего) для полоски "2 из 5".
    SUM(is_done) — сумма нулей и единиц = число выполненных.
    Считается одним запросом в базе, а не загрузкой всех подзадач в
    Python — карточек много, так быстрее.

set_subtask_done(subtask_id, is_done), delete_subtask(subtask_id)
    Точечные операции с одной подзадачей. Сейчас окно задачи
    пользуется схемой "clear + add заново", но методы оставлены для
    полноты CRUD.


close()
-------
Закрывает соединение с базой. Вызывается из main.py после выхода из
цикла событий.


ВОЗМОЖНЫЕ ВОПРОСЫ НА ЗАЩИТЕ
---------------------------
В: Где у тебя создаётся база?
О: sqlite3.connect создаёт файл сам, если его нет; таблицы создаёт
   _create_tables через CREATE TABLE IF NOT EXISTS.

В: Как удаляются подзадачи при удалении задачи?
О: ON DELETE CASCADE в таблице subtasks. И обязательно
   PRAGMA foreign_keys = ON — без неё SQLite каскад не выполняет.

В: Что такое commit?
О: Фиксация транзакции — изменения окончательно записываются в файл.

В: Как защищаешься от SQL-инъекций?
О: Все значения передаются через параметры "?", а не склеиваются
   со строкой запроса.
