==========================================================================
 main_window.py — главное окно приложения
==========================================================================

ЗАЧЕМ НУЖЕН ФАЙЛ
----------------
Внешний вид главного окна описан в ui/main_window.ui (сделан в Qt
Designer). Этот файл отвечает за ПОВЕДЕНИЕ окна:
  - переключение режимов "Календарь" / "Все задачи";
  - заполнение списков карточками задач из базы;
  - поиск и фильтр по категории;
  - открытие окна задачи и окна категорий;
  - горячие клавиши (клавиатура) и контекстное меню (мышь).

Разделение: .ui — "как выглядит", .py — "что происходит". Если поменять
вид в Designer, код обычно трогать не нужно — лишь бы не менялись
objectName виджетов.

      Особый импорт. Напрямую TaskCalendar в коде не используется —

КЛАСС MainWindow(QMainWindow)
-----------------------------
Наследуется от QMainWindow — того же класса, что корневой виджет в
main_window.ui. Это обязательно для uic.loadUi(путь, self).


КОНСТРУКТОР __init__(self, database, parent=None)
-------------------------------------------------
  super().__init__(parent) — конструктор родителя QMainWindow.
  self._db = database — база передана из main.py.
  self._categories_by_id = {} — словарь {id: категория}. Карточкам
      нужен цвет и название категории; держим их в словаре, чтобы не
      обращаться к базе для каждой карточки.

  uic.loadUi(MAIN_WINDOW_UI, self)
      КЛЮЧЕВАЯ СТРОКА. Читает XML формы и ДОСТРАИВАЕТ объект self:
      создаёт все виджеты формы и делает их атрибутами. Кнопка с
      objectName "newTaskButton" становится self.newTaskButton,
      календарь — self.calendarWidget и т.д.
      Альтернатива — компилировать .ui в .py утилитой pyuic5. Мы
      грузим напрямую: форму можно править в Designer без
      перегенерации кода.

  setWindowTitle, setMinimumSize — заголовок и минимальный размер.

  Дальше по шагам:
    _prepare_icons()      — иконки на кнопках;
    _prepare_calendar()   — цвета шапки календаря;
    _connect_signals()    — подключение сигналов и горячих клавиш;
    _reload_categories()  — заполнение фильтра категорий;
    setSelectedDate(QDate.currentDate()) — в календаре выбран сегодня;
    _switch_mode(MODE_CALENDAR_INDEX)    — стартовый режим;
    refresh()             — загрузить задачи в списки.


_prepare_icons()
----------------
Иконки — картинки из assets/icons (тоже закрывают критерий
"мультимедиа"). Обычно в Designer их подключают через файл ресурсов
.qrc, но формы у нас грузятся напрямую, поэтому иконки назначаются
кодом: путь один — из constants.py.

  Кортеж пар (кнопка, путь) и цикл: button.setIcon(QIcon(путь)),
  button.setIconSize(QSize(18, 18)).

  self.searchLineEdit.addAction(QIcon(ICON_SEARCH),
                                QLineEdit.LeadingPosition)
      Значок лупы ВНУТРИ поля поиска, слева. Qt сам сдвигает текст.

  self.setWindowIcon(...) — иконка в заголовке и на панели задач.


_prepare_calendar()
-------------------
Сами дни рисует TaskCalendar, а строку с названиями дней недели
(Пн, Вт, ...) Qt рисует сам. Ей цвет задаётся форматом текста:
  header_format = QTextCharFormat()
  setForeground — цвет текста, setBackground — фон.
  self.calendarWidget.setHeaderTextFormat(header_format)

  Qt по умолчанию красит субботу и воскресенье КРАСНЫМ. У нас красный
  значит "просрочено", поэтому для Qt.Saturday и Qt.Sunday тоже
  задаётся серый формат через setWeekdayTextFormat.


_connect_signals() — СИГНАЛЫ И СЛОТЫ
------------------------------------
Сигнал — оповещение виджета (нажали кнопку, изменился текст). Слот —
метод, который на него реагирует. Запись
    widget.signal.connect(self.method)
читается как "когда произойдёт signal, вызови self.method". Qt сам
вызовет метод — не нужно в цикле проверять, нажата ли кнопка.

  calendarModeButton.clicked -> lambda: self._switch_mode(0)
  allTasksModeButton.clicked -> lambda: self._switch_mode(1)
      Зачем lambda: сигнал clicked передаёт слоту свой аргумент
      (checked — нажата ли кнопка), а нам нужно передать номер режима.
      lambda — маленькая безымянная функция, которая вызывает нужный
      метод с нужным аргументом.

  calendarWidget.selectionChanged -> _refresh_day_tasks
      Клик по дню календаря (МЫШЬ) — обновить список задач дня.

  searchLineEdit.textChanged -> _refresh_all_tasks
      Срабатывает на каждый введённый символ — поиск "на лету", без
      кнопки "Найти".

  categoryFilterComboBox.currentIndexChanged -> _refresh_all_tasks
      Смена категории в фильтре.

  newTaskButton.clicked -> lambda: self._open_task_dialog()
      lambda здесь нужна, чтобы аргумент checked от clicked не попал в
      параметр task_id. Без аргументов task_id = None — режим создания.

  categoriesButton.clicked -> _open_categories_dialog

  _create_shortcuts() — горячие клавиши.


_create_shortcuts() — КЛАВИАТУРА
--------------------------------
QShortcut(QKeySequence("Ctrl+N"), self) — горячая клавиша, привязанная
к окну self. Её сигнал activated подключается к методу.

  Словарь {сочетание: обработчик}:
    Ctrl+N — новая задача;
    Ctrl+F — перейти к поиску (_focus_search);
    Ctrl+1 — режим "Календарь";
    Ctrl+2 — режим "Все задачи".
  Цикл for создаёт QShortcut для каждой пары.

  Delete и Enter привязаны не к окну, а к каждому СПИСКУ задач, с
  контекстом Qt.WidgetShortcut — "работает только когда фокус в этом
  виджете". Иначе Delete, нажатый во время набора текста в поиске,
  удалял бы задачу вместо символа.
  Qt.Key_Return — основной Enter, Qt.Key_Enter — Enter на цифровом
  блоке; подключены оба.

  Esc для закрытия окна задачи не нужно программировать: QDialog
  обрабатывает Esc сам (вызывает reject()).


_focus_search()
---------------
Ctrl+F: переключиться на "Все задачи", поставить курсор в поиск
(setFocus) и выделить старый текст (selectAll), чтобы сразу печатать.


_switch_mode(mode_index)
------------------------
QStackedWidget — "стопка страниц", из которой видна одна.
  setCurrentIndex(mode_index) — показать нужную страницу.
Кнопки режимов в Designer отмечены как checkable (могут быть
"нажатыми"). Активную отмечаем, вторую снимаем:
  setChecked(mode_index == MODE_CALENDAR_INDEX) — True/False.


_reload_categories()
--------------------
Перечитывает категории: заполняет словарь _categories_by_id и фильтр.
  {row["id"]: row for row in categories} — генератор словаря.

  В QComboBox каждый пункт хранит видимый текст и СКРЫТЫЕ ДАННЫЕ
  (второй аргумент addItem). Мы кладём туда id категории, а у пункта
  "Все категории" — None. Так по выбору сразу получаем id, не сравнивая
  названия.

  blockSignals(True) ... blockSignals(False)
      Временно отключает сигналы виджета. При clear() и addItem()
      сигнал currentIndexChanged сработал бы несколько раз и зря
      перерисовывал бы список задач.

_selected_category_id()
    currentData() — скрытые данные выбранного пункта (id или None).


refresh() — ЕДИНАЯ ТОЧКА ОБНОВЛЕНИЯ
-----------------------------------
Перечитывает всё из базы: отметки в календаре, список дня, список
всех задач. После любого изменения данных достаточно вызвать
refresh() — окно придёт в соответствие с базой.


_mark_calendar_deadlines()
--------------------------
Собирает словарь {QDate: есть_просрочка} и передаёт календарю.
  - Пропускаем задачи без срока и выполненные (continue).
  - QDate.fromString(строка, формат) — строка из базы в QDate.
  - is_overdue = deadline < today — QDate можно сравнивать.
  - deadline_days.get(deadline, False) or is_overdue
      Если в один день попали обычная и просроченная задача, день
      должен остаться красным — поэтому объединяем через "или".
      .get(ключ, False) — значение или False, если ключа ещё нет.
  - calendarWidget.set_deadline_days(...) — метод нашего TaskCalendar.


_refresh_day_tasks()
--------------------
  selected_date = calendarWidget.selectedDate()
  Подпись "Задачи на 27.09.2026": selected_date.toString(формат_показа).
  Задачи из базы по дате в формате базы (get_tasks_by_date).
  _fill_task_list(...) — наполнить список карточками.


_refresh_all_tasks() и _filtered_tasks()
----------------------------------------
Берём все задачи и отбираем в Python:
  - если выбрана категория и у задачи другая — пропустить;
  - если в поиске есть текст и его нет в названии — пропустить.
  .strip().lower() — убрать пробелы по краям и привести к нижнему
  регистру: поиск не зависит от заглавных букв.
Фильтрация в Python, а не в SQL: задач немного, а условия читаются
проще, чем склеенный SQL-запрос.


_fill_task_list(list_widget, tasks, empty_text)
-----------------------------------------------
  list_widget.clear() — убрать старые пункты (и карточки).
  Если задач нет — добавляется пункт-заглушка с текстом ("Задач пока
  нет") и флагами Qt.NoItemFlags: его нельзя выделить и удалить.
  Иначе для каждой задачи — _add_task_card.


_add_task_card(list_widget, task) — ВИДЖЕТ ВНУТРИ СПИСКА
--------------------------------------------------------
  1) count_subtasks — сколько подзадач выполнено/всего.
  2) card = TaskCard(task, категория, done, total)
     Категория берётся из словаря: .get(id) вернёт None, если
     категории нет.
  3) Подключаем сигналы карточки к методам окна:
       doneToggled   -> _on_task_done_toggled   (галочка)
       openRequested -> _open_task_dialog       (двойной клик)
       clicked       -> _select_task            (клик)
       menuRequested -> _show_task_menu         (правый клик)
  4) item = QListWidgetItem() — пустой пункт списка.
     item.setData(Qt.UserRole, task["id"])
       РОЛИ ДАННЫХ: пункт хранит несколько "ячеек". В Qt.DisplayRole —
       видимый текст, а Qt.UserRole свободна для наших данных. Кладём
       туда id задачи — по выделенному пункту всегда знаем, какую
       задачу открыть или удалить.
  5) item.setSizeHint(...) — пункт сам не знает размер вложенного
     виджета, его нужно сообщить, иначе карточка обрежется.
     max(высота_карточки, CARD_MIN_HEIGHT) — не меньше минимума.
  6) list_widget.addItem(item)
     list_widget.setItemWidget(item, card) — вместо текста пункта
     рисуется наш виджет-карточка.


_open_task_dialog(task_id=None)
-------------------------------
  dialog = TaskDialog(self._db, task_id, self)
  if dialog.exec_() == QDialog.Accepted: self.refresh()

  exec_() показывает диалог МОДАЛЬНО: главное окно заблокировано, код
  ждёт закрытия диалога. Возвращает результат:
    QDialog.Accepted — нажали "Сохранить" или "Удалить" (accept());
    QDialog.Rejected — "Отмена", Esc или крестик (reject()).
  Списки перечитываем только если что-то изменилось.


_open_categories_dialog()
-------------------------
  Открывает окно категорий. После закрытия:
  - запоминает выбранную в фильтре категорию;
  - перечитывает категории (могли переименовать/удалить/перекрасить);
  - findData(id) ищет пункт с этим id; если категорию удалили, вернёт
    -1, и max(-1, 0) = 0 выберет "Все категории";
  - refresh() — у карточек могли измениться цвета полосок.


ВЫДЕЛЕНИЕ, КЛАВИАТУРА, МЕНЮ
---------------------------
_current_task_list()
    Список того режима, который сейчас открыт.

_select_task(task_id)
    Перебирает пункты текущего списка, находит пункт с нужным id в
    UserRole, выделяет (setCurrentItem) и ставит фокус в список —
    чтобы сразу работали Delete и Enter. Нужен потому, что карточка
    перехватывает клик и QListWidget его не видит.

_selected_task_id()
    id выделенной задачи или None.

_open_selected_task()   — Enter: открыть выделенную задачу.
_delete_selected_task() — Delete: удалить выделенную задачу.

_delete_task(task_id)
    Берёт задачу из базы (для названия в вопросе), спрашивает
    ask_yes_no "Удалить задачу «...»?". При "Да" — delete_task и
    refresh.

_show_task_menu(task_id, global_position) — КОНТЕКСТНОЕ МЕНЮ (МЫШЬ)
    menu = QMenu(self)
    open_action = menu.addAction("Открыть") — addAction возвращает
        объект-действие (QAction), по нему потом узнаем выбор.
    done_action — setCheckable(True) и setChecked(...) — пункт с
        галочкой, отражает текущее состояние задачи.
    menu.addSeparator() — разделительная линия.
    delete_action = menu.addAction("Удалить")

    chosen_action = menu.exec_(global_position)
        Показывает меню в точке экрана и ждёт выбора. Возвращает
        выбранное действие или None, если меню закрыли.
    Дальше сравниваем, какой пункт выбран, и выполняем действие.
    Меню собирается заново на каждый клик, чтобы галочка
    "Выполнено" всегда была актуальной.


_on_task_done_toggled(task_id, is_done) — ГАЛОЧКА НА КАРТОЧКЕ
-------------------------------------------------------------
  self._db.set_task_done(task_id, is_done) — записать в базу.
  QTimer.singleShot(0, self.refresh) — ОТЛОЖЕННОЕ обновление.

  Почему не просто self.refresh(): refresh() пересоздаёт все карточки,
  то есть удаляет в том числе ту, чей чекбокс ПРЯМО СЕЙЧАС
  обрабатывает нажатие. Удалить виджет внутри его же обработчика
  нельзя: после возврата Qt продолжит работать с уже удалённым
  объектом, и приложение упадёт.
  QTimer.singleShot(0, ...) ставит вызов в очередь событий: refresh
  выполнится сразу ПОСЛЕ того, как обработка клика полностью
  закончится. 0 — "без задержки, но в следующем витке цикла событий".


КАК ЗАКРЫВАЮТСЯ КРИТЕРИИ В ЭТОМ ФАЙЛЕ
-------------------------------------
  Клавиатура: QShortcut (Ctrl+N, Ctrl+F, Ctrl+1/2, Delete, Enter).
  Мышь: клик по дню календаря, клик/двойной клик/правый клик по

ВОЗМОЖНЫЕ ВОПРОСЫ НА ЗАЩИТЕ
---------------------------
В: Как форма из Designer связана с кодом?
О: uic.loadUi(путь, self) создаёт виджеты формы и делает их атрибутами
   окна по objectName.

В: Почему Delete не срабатывает при наборе в поиске?
О: Shortcut Delete привязан к списку задач с контекстом WidgetShortcut —
   он работает только когда фокус в списке.

В: Зачем QTimer.singleShot(0, ...)?
О: Чтобы не удалять карточку внутри обработчика её же чекбокса —
   обновление выполняется после завершения обработки клика.

В: Как список знает, какая задача в пункте?
О: id хранится в пункте через setData(Qt.UserRole, id).

В: Что такое lambda в connect?
О: Короткая функция-обёртка, чтобы передать методу нужный аргумент
   вместо того, что передаёт сигнал.
