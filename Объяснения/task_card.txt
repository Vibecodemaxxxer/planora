==========================================================================
 task_card.py — карточка задачи в списке
==========================================================================

ЗАЧЕМ НУЖЕН ФАЙЛ
----------------
Карточка — это собственный виджет, который вставляется в QListWidget
вместо обычной текстовой строки. На ней:
  [цветная полоска] Название ........ Сегодня  Высокий  [мини] [✓]
                    [██████░░░░ 2 из 5]

Почему отдельный файл, а не часть main_window.py:
  1. Карточка используется в двух списках (задачи дня и "Все задачи") —
     это самостоятельный элемент, а не часть одного окна.
  2. main_window.py и так большой; сборка карточки смешала бы две разные
     задачи в одном файле.

Почему карточка собрана кодом, а не в Qt Designer: карточек создаются
десятки (по одной на задачу), и они пересоздаются при каждом обновлении
списка. Такой виджет удобнее собирать в цикле. Требование "не меньше
двух форм из Designer" выполнено тремя окнами приложения.


ИМПОРТЫ
-------
  QDate — работа с датами; QPoint — точка на экране; Qt — константы;
  pyqtSignal — объявление собственных сигналов;
  QPixmap — картинка (миниатюра);
  QCheckBox, QFrame, QHBoxLayout, QLabel, QProgressBar, QVBoxLayout,
  QWidget — виджеты и раскладки, из которых собирается карточка.


ФУНКЦИЯ deadline_state(deadline_iso, is_done)
---------------------------------------------
Функция вне класса (её можно использовать и отдельно). Вычисляет
состояние задачи по сроку и возвращает пару (текст метки, цвет).

Состояние НЕ ХРАНИТСЯ в базе, а считается каждый раз заново. Если бы
"Сегодня" было записано в базу, то в полночь пришлось бы переписывать
все задачи. А так метка всегда актуальна.

Порядок проверок важен:
  1) is_done -> "Выполнено" (зелёный). Выполненная задача считается
     выполненной, даже если срок прошёл.
  2) нет срока -> "Без срока".
  3) Строка из базы превращается в QDate:
         deadline = QDate.fromString(deadline_iso, DATE_FORMAT_DB)
     days_left = QDate.currentDate().daysTo(deadline)
         daysTo — сколько дней от сегодня до срока. Отрицательное число —
         срок в прошлом.
  4) days_left < 0  -> "Просрочено" (красный)
     days_left == 0 -> "Сегодня" (оранжевый)
     days_left == 1 -> "Завтра"
     иначе          -> "Через N дн." (серый) — N подставляется в шаблон.


КЛАСС TaskCard(QWidget)
-----------------------
Главная идея: КАРТОЧКА НИЧЕГО НЕ ЗНАЕТ ПРО БАЗУ ДАННЫХ. Она только
показывает переданные ей данные, а о действиях пользователя сообщает
наружу сигналами. В базу пишет главное окно. Поэтому карточку можно
вставить в любой список, не меняя её код.


СОБСТВЕННЫЕ СИГНАЛЫ (важная тема PyQt!)
---------------------------------------
    doneToggled   = pyqtSignal(int, bool)
    openRequested = pyqtSignal(int)
    clicked       = pyqtSignal(int)
    menuRequested = pyqtSignal(int, QPoint)

Сигнал — это "оповещение", которое объект рассылает, когда что-то
произошло. Другие объекты подписываются на него через .connect(метод),
и Qt сам вызывает их методы, когда сигнал "испущен" (.emit(...)).

Сигналы объявляются на уровне КЛАССА (не в __init__) — так требует
PyQt. В скобках — типы аргументов, которые сигнал передаёт.

  doneToggled(id, состояние) — нажали галочку "выполнено";
  openRequested(id)          — двойной клик, просят открыть задачу;
  clicked(id)                — одиночный клик, карточку выбрали;
  menuRequested(id, точка)   — правый клик, нужна точка экрана для меню.

В main_window.py:
  card.doneToggled.connect(self._on_task_done_toggled)
  card.openRequested.connect(self._open_task_dialog)
  ...
А внутри карточки:  self.doneToggled.emit(self._task_id, is_checked)


КОНСТРУКТОР __init__(self, task, category, subtasks_done,
                     subtasks_total, parent=None)
-----------------------------------------------------------
Параметры: строка задачи из базы, строка категории (или None),
число выполненных подзадач и общее число.

  self._task_id = task["id"] — запоминаем id, чтобы при любом действии
      сообщать, о какой задаче речь.
  self.setObjectName("taskCard") — имя для QSS: в style.qss можно
      написать правило #taskCard { ... } именно для карточек.
  self.setMinimumHeight(CARD_MIN_HEIGHT)
  self.setToolTip(...) — подсказка при наведении "Категория: Учёба".
      На самой карточке категорию обозначает только цветная полоска.

  layout = QHBoxLayout(self)
      Горизонтальная раскладка: элементы идут слева направо. Раскладка
      (layout) сама расставляет и растягивает виджеты при изменении
      размера окна — координаты вручную не задаём.
  setContentsMargins — внутренние отступы от краёв карточки.
  setSpacing — промежуток между элементами.

  Слева направо добавляются:
    1) цветная полоска (_create_color_bar);
    2) центральная часть (_create_content) с коэффициентом растяжения 1:
       она забирает всё свободное место, поэтому остальные элементы
       прижимаются к правому краю;
    3) миниатюра картинки — только если она есть (не None);
    4) галочка "выполнено".

@property task_id
    Позволяет читать card.task_id снаружи как атрибут, но не менять его.


СОСТАВНЫЕ ЧАСТИ КАРТОЧКИ
------------------------
_create_color_bar(category) — @staticmethod
    QFrame шириной 4 px. Цвет категории задаётся прямо в коде через
    setStyleSheet(f"background-color: {color}; ..."), потому что цвет у
    каждой категории свой и берётся из базы — в общем style.qss его
    не пропишешь. Нет категории — серый цвет по умолчанию.

_create_content(task, subtasks_done, subtasks_total)
    QVBoxLayout — вертикальная раскладка (сверху вниз):
      строка названия (_create_title_row);
      полоска прогресса — ТОЛЬКО если подзадачи есть (subtasks_total
      не 0). alignment=Qt.AlignLeft — полоска прижата влево и не
      растягивается на всю ширину.

_create_title_row(task)
    Горизонтальная строка: название, "пружина" addStretch(), метка
    срока, приоритет. Пружина забирает свободное место — название
    прижимается влево, метки вправо.

_create_title_label(task)
    QLabel с названием. Берём текущий шрифт метки (font()), делаем
    жирным и зачёркнутым, если задача выполнена (setStrikeOut). Берём
    именно текущий шрифт, чтобы не сбить размер, заданный стилем.

_create_deadline_label(task)
    Вызывает deadline_state(...) и красит текст в полученный цвет.

_create_priority_label(task)
    Цвет из PRIORITY_COLORS. Используется .get(priority, запасной_цвет):
    если в базе окажется неизвестный приоритет, не будет KeyError.

_create_progress_bar(done, total)
    QProgressBar: setMaximum(total), setValue(done). По умолчанию Qt
    пишет проценты, но нам нужна подпись "2 из 5" — задаём её явно
    через setFormat. Размеры фиксированные.

_create_thumbnail(task)
    Миниатюра прикреплённой картинки 38x38 или None.
    В базе хранится только ПУТЬ к файлу, а файл могли удалить. Поэтому:
      pixmap = QPixmap(путь)
      if pixmap.isNull(): return None  — файл не читается, без миниатюры.
    pixmap.scaled(..., Qt.KeepAspectRatioByExpanding,
                  Qt.SmoothTransformation)
      KeepAspectRatioByExpanding — заполнить квадрат целиком, сохранив
      пропорции (лишнее обрезается). SmoothTransformation — сглаживание
      при уменьшении.

_create_done_checkbox(task)
    QCheckBox "выполнено".
    ВАЖЕН ПОРЯДОК: сначала setChecked(...), и только ПОТОМ
    toggled.connect(...). Если подключить сигнал раньше, setChecked при
    создании карточки сам вызвал бы обработчик, и задача
    "переключилась" бы в базе без участия пользователя.


МЫШЬ: ОБРАБОТЧИКИ СОБЫТИЙ
-------------------------
Кроме сигналов в Qt есть СОБЫТИЯ (events). Разница:
  - сигнал — на него подписываются через connect;
  - событие приходит виджету само: Qt вызывает у виджета метод со
    специальным именем (mousePressEvent, mouseDoubleClickEvent,
    contextMenuEvent...). Достаточно определить метод с таким именем.

_on_done_toggled(is_checked)
    Обработчик сигнала галочки. Пересылает нажатие наружу, добавив id:
        self.doneToggled.emit(self._task_id, is_checked)

mousePressEvent(event) — нажатие кнопки мыши на карточке.
    Карточка закрывает собой пункт списка, поэтому сам QListWidget
    клика не видит и выделение не переносит. Карточка сообщает сигналом
    clicked, главное окно выделяет нужный пункт — и тогда работают
    клавиши Delete и Enter.
    super().mousePressEvent(event) — вызываем стандартную обработку,
    чтобы ничего штатного не потерять.

contextMenuEvent(event) — правый клик (или клавиша меню на клавиатуре).
    Карточка не строит меню сама — у неё нет доступа к базе. Она
    отправляет сигнал menuRequested с id и event.globalPos() — точкой
    в координатах ЭКРАНА (а не карточки), чтобы меню появилось под
    курсором.

mouseDoubleClickEvent(event) — двойной клик.
    Испускает openRequested(id) — главное окно откроет окно задачи.


ВОЗМОЖНЫЕ ВОПРОСЫ НА ЗАЩИТЕ
---------------------------
В: Чем сигнал отличается от события?
О: Событие Qt передаёт виджету вызовом метода с особым именем
   (mousePressEvent). Сигнал — оповещение, на которое любой объект
   может подписаться через connect.

В: Зачем свои сигналы, почему карточка не пишет в базу сама?
О: Чтобы карточка была независимой: она только показывает данные.
   Логику и работу с базой держит главное окно.

В: Почему состояние "Сегодня" не хранится в базе?
О: Оно зависит от текущей даты и меняется каждые сутки само собой.
   Считать его при отрисовке проще и надёжнее.

В: Что будет, если удалить файл картинки?
О: QPixmap окажется пустым (isNull), миниатюра просто не покажется,
   программа не упадёт.
